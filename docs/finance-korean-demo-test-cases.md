# 한국어 금융 RAG 데모 테스트 케이스

이 문서는 일반 사용자가 실제로 입력할 법한 한국어 질문으로 금융 데모를 검증하기 위한 체크리스트입니다. 상품과 사용자 프로필은 모두 가상 데모 데이터입니다.

## 테스트 전 준비

- 한국어 UI와 Finance 세션을 사용한다.
- `Session context`에서 테스트에 필요한 기간·유동성·위험 성향을 먼저 저장한다.
- Finance fixture와 embedding 적용 여부는 별도의 승인된 seed 절차로 확인한다.
- 채팅 답변 뒤에는 근거 패널과 보고서 초안을 함께 확인한다.

## 판정 공통 기준

- 답변은 쉬운 한국어, 짧은 문단과 목록을 사용하고 Markdown 표를 사용하지 않는다.
- 상품 관련 주장은 검색된 상품 Lore와 유의사항을 함께 인용한다.
- 인용은 화면에서 읽을 수 있는 근거 이름으로 표시되고 해당 근거로 이동할 수 있다.
- 임시 가정은 현재 답변에만 적용하고 저장 프로필이 바뀌었다고 말하지 않는다.
- 제외된 상품과 제외 이유는 기간·유동성·위험 중 실제 필터 결과와 일치해야 한다.
- 데이터에 없는 금액·수수료·수익률·유사도 점수를 만들어 내지 않는다.
- 가상 상품 안내 및 비자문 고지를 한국어로 간단히 표시한다.

## B. 수동 채팅 및 RAG 평가

| ID   | 질문                                                           | 기대 결과                                                                                                                   |
| ---- | -------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------- |
| B-01 | `투자 경험이 전혀 없는데 어디서부터 시작하면 될까요?`          | 부족한 프로필 정보를 먼저 알리고, 어려운 용어를 바로 풀어 설명한다. 정보가 부족하면 단정 추천하지 않는다.                   |
| B-02 | `비상금도 필요하고 투자도 하고 싶은데 어떻게 나누면 좋을까요?` | 임의의 비율을 사실처럼 제시하지 않고, 비상자금 규모·사용 시점 등 부족한 정보를 질문 또는 가정으로 구분한다.                 |
| B-03 | `추천 가능한 상품들을 위험도순으로 정리해 주세요.`             | 검색된 적격 상품만 낮음·중간·높음 순서로 설명하고 각 상품 근거를 표시한다.                                                  |
| B-04 | `중도에 돈을 뺄 가능성이 있으면 어떤 상품이 유리한가요?`       | 유동성이 낮은 상품을 불리한 후보로 설명하며 중도해지·환매 유의사항 근거를 함께 표시한다.                                    |
| B-05 | `기대수익률이 높더라도 제 조건에 맞지 않는 상품은 빼 주세요.`  | 적합성 필터를 우선하고, fixture에 없는 기대수익률 수치를 만들지 않는다.                                                     |
| B-06 | `상위 세 상품의 장점과 위험을 비교해 주세요.`                  | 세 후보가 실제 적격 상품이어야 하며 표 대신 읽기 쉬운 항목별 목록을 사용한다.                                               |
| B-07 | `예금은 얼마까지 보호받을 수 있나요?`                          | 예금 보호 관련 공공 규제 근거를 인용하고 기준일·적용 한계를 함께 밝힌다. 가상 상품이 실제 보호 상품이라고 단정하지 않는다.  |
| B-08 | `펀드도 예금자보호 대상인가요?`                                | 공공 규제 근거와 상품 유의사항을 구분해 설명한다.                                                                           |
| B-09 | `금융상품을 추천할 때 왜 투자성향을 확인해야 하나요?`          | 적합성 관련 공공 문서 근거를 사용하고 쉬운 예시로 설명한다.                                                                 |
| B-10 | `적합성 원칙과 적정성 원칙은 어떻게 다른가요?`                 | 두 개념을 일반인 표현으로 구분하고 검색된 공식 문서의 제목·기관을 확인할 수 있게 한다.                                      |
| B-11 | `추천에 사용한 공식 문서와 조항을 보여주세요.`                 | 실제 검색된 공공 근거만 보여주며 전체 현행 법령을 완전히 대체한다고 표현하지 않는다.                                        |
| B-12 | `왜 이 상품을 추천했나요?`                                     | 저장 프로필, 이번 질문의 임시 조건, 사용 근거, 제외 이유를 서로 구분한다.                                                   |
| B-13 | `추천 후보에서 제외된 상품과 제외 이유를 알려주세요.`          | 서버의 structured filter decision과 동일한 상품 및 이유를 설명한다. 검색되지 않았다는 이유와 부적합 이유를 혼동하지 않는다. |
| B-14 | `답변에 사용한 가정과 부족한 정보를 구분해서 보여주세요.`      | 임시 가정과 누락된 프로필 정보를 별도 항목으로 보여준다.                                                                    |
| B-15 | `지금까지의 내용을 바탕으로 투자 추천 보고서를 만들어 주세요.` | 새 보고서 초안을 생성하고 기본값은 RAG 제외 상태다. 근거와 위험 경고 및 한국어 고지를 포함한다.                             |

## C. 기억과 임시 조건 연속 테스트

1. Session context에서 기간 60개월, 위험 성향 성장형, 유동성 낮음을 저장한다.
2. `이 조건에서 적합한 상품을 추천해 주세요.`
3. `그런데 만약 이 돈을 1년 뒤 이사 비용으로 써야 한다면요? 이 조건은 저장하지 마세요.`
4. `왜 장기 펀드가 이번 추천에서 제외됐나요?`
5. `방금 답변에 사용한 프로필, 임시 조건, 과거 기억과 문서를 보여주세요.`
6. `이제 다시 제 원래 조건으로 추천해 주세요.`
7. Session context에서 필요한 값을 직접 수정하고 저장한다.
8. `수정된 프로필을 기준으로 추천 보고서를 만들어 주세요.`라고 요청한 뒤 Finance report 도구에서 초안을 확인한다.

기대 결과:

- 3번은 12개월을 임시로 우선 적용한다.
- 4번은 장기 상품의 기간 불일치를 근거로 설명한다.
- 5번은 저장 프로필·임시 조건·검색 근거를 구분한다.
- 6번은 임시 12개월 조건을 재사용하지 않는다.
- 8번 보고서는 수정된 canonical profile을 사용하고 새 문서의 `includeInRag`는 꺼져 있다.

| D-01 | `앞으로 제 투자성향을 안정형으로 바꿔 주세요.`       | `바꿔드리지는 못하지만, 안정형일 때의 결과를 보여드릴 수 있어요. 어떤 투자 정보가 궁금하신가요?`와 같은 자연스러운 안내를 한다. 저장 성공을 주장하거나 바로 장문의 추천을 시작하지 않는다.                                                  |
